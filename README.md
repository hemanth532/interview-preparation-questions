# Interview Preparation Knowledge Base

A structured, searchable knowledge base for Senior Frontend, Full Stack, and AI Engineer interview preparation.

## Goals
- Keep every interview question in one place.
- Separate fundamentals, advanced topics, system design, AI/ML, and behavioral questions.
- Track company-specific interview questions.
- Record confidence, review status, and follow-up questions.
- Reuse answers across future interviews.

## Repository Structure

- [Frontend](frontend/README.md) — Angular, React, JavaScript, TypeScript, performance, testing
- [Backend](backend/README.md) — Node.js, Python, .NET, APIs, async programming
- [Database](database/README.md) — SQL, MongoDB, data modeling
- [AI & ML](ai-ml/README.md) — ML, GenAI, RAG, agents, LangChain, LangGraph, MCP
- [System Design](system-design/README.md) — architecture, microservices, real-time platforms
- [Cloud & DevOps](cloud-devops/README.md) — AWS, Docker, Kubernetes, CI/CD, observability
- [Security](security/README.md) — OAuth, JWT, Keycloak, Azure AD, CORS
- [Behavioral](behavioral/README.md) — STAR, leadership, project experience
- [Companies](companies/README.md) — company/client-specific questions
- [Templates](templates/README.md) — reusable question and topic templates

## Question Format

Every question should ideally contain:
1. Question
2. Short interview answer
3. Detailed explanation
4. Example/code when applicable
5. Key points
6. Follow-up questions
7. Common mistakes
8. Confidence/review status

## Difficulty

- 🟢 Easy
- 🟡 Medium
- 🔴 Hard
- 🟣 Expert

## Review Status

- ⬜ Not started
- 🟡 Reviewing
- 🟢 Confident
- 🔁 Needs review

## Quick Study Workflow

1. Add the question to the appropriate topic.
2. Write a 30–60 second answer.
3. Add the deeper explanation.
4. Add follow-up questions.
5. Mark confidence.
6. Review weak questions before each interview.

## Interview Question Index

Use the topic READMEs as indexes. Company-specific questions should also be linked from `companies/`.
