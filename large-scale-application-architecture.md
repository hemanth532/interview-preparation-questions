# 06. Large-Scale Application Architecture Interview Questions

## Questions

1. How would you architect a large Angular enterprise application?
2. How would you divide the application into domains?
3. How would you decide between a monolith, modular monolith, and micro frontends?
4. How would you structure an Angular project with 20+ development teams?
5. How do you prevent different teams from tightly coupling their modules?
6. How would you design shared libraries?
7. What should be shared and what should remain domain-specific?
8. How would you manage application-wide state?
9. How would you handle cross-team API contracts?
10. How would you maintain backward compatibility?
11. How would you manage breaking changes?
12. How would you implement feature flags?
13. How would you design a highly available frontend architecture?
14. How would you design a frontend application that supports millions of users?
15. How would you improve application startup time?
16. How would you handle large datasets in the UI?
17. How would you implement caching?
18. CDN caching vs browser caching vs API caching?
19. How would you design observability for the entire system?

## Design Principles

- Domain ownership
- Loose coupling
- High cohesion
- API contracts
- Independent deployments
- Backward compatibility
- Automated testing
- Observability
- Security by design
- Performance budgets
